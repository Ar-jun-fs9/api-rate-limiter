API Rate Limiter

A production-ready rate limiting system with per-key and per-endpoint controls powered by Django & Redis

What is this project?

🔑
Per-API Key Limits

Each API key has its own request quota. Generate multiple keys for different clients or use cases with individual rate limits.

🎯
Per-Endpoint Limits

Different endpoints can enforce different rate limits. Sensitive endpoints like login can have stricter limits than read-only endpoints.

⚡
Redis Powered

Uses Upstash Redis for blazing fast, distributed rate tracking. The sliding window counter ensures accurate throttling.

📊
Response Headers

Every response includes X-RateLimit-Limit and X-RateLimit-Remaining headers so clients can track their quota.

📋 Using Postman

1

Create a New Request

Open Postman, click "New" and select "HTTP Request". Choose GET method.

2

Enter the URL

Local: http://127.0.0.1:8000/api/test/
Render: https://api-rate-limiter-lo1o.onrender.com/api/test/

3

Add the API Key Header

Go to Headers tab, add:

Key: X-API-Key Value: YOUR_API_KEY_UUID
4

Send & Verify

Click Send. Check the response headers for X-RateLimit-Limit and X-RateLimit-Remaining. Make 10+ requests to trigger rate limiting.

💻 Using cURL

Open your terminal and run these commands:

$ curl -H "X-API-Key: YOUR_API_KEY" http://127.0.0.1:8000/api/test/

Check response headers:

$ curl -i -H "X-API-Key: YOUR_API_KEY" http://127.0.0.1:8000/api/test/

Test rate limiting (make 12 requests):

$ for i in {1..12}; do curl -s -H "X-API-Key: YOUR_API_KEY" http://127.0.0.1:8000/api/test/; echo; done

🔍 Manual Verification

How to manually verify the rate limiter is working:

✓

Without API Key

Send a request without X-API-Key header. Expected: 401 {"detail": "API key required"}

✓

With Invalid API Key

Send a request with a fake UUID. Expected: 401 {"detail": "Invalid API key"}

✓

Successful Request

With valid key under limit. Expected: 200 + X-RateLimit-Limit, X-RateLimit-Remaining headers

✓

Rate Limit Exceeded

Make more than the allowed requests. Expected: 429 {"detail": "Rate limit exceeded"}

Use Cases

🏢
SaaS Applications

Control API usage for different subscription tiers. Free tier gets 100 req/min, Pro gets 1000 req/min, Enterprise gets unlimited access.

🤖
Bot Protection

Prevent aggressive scraping or bot abuse by limiting request rates per client. Protects your backend services from overload.

📱
Mobile Apps

Throttle API calls from mobile clients to reduce server load and prevent abuse. Track per-device usage with unique keys.

🔗
Third-Party Integrations

Give external partners limited API access with custom rate limits. Revoke keys instantly if abuse is detected.

🧪
Testing & Development

Use rate limiting in staging environments to simulate production conditions. Test how your client handles 429 responses.

⚖️
API Monetization

Offer paid API access with tiered rate limits. Charge based on allowed requests per minute.

Configuration

🔧 Environment Variables

Create a .env file in the project root:
