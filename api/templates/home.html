Welcome to API Rate Limiter Project

Test and manage API requests with per-key and per-endpoint rate limits.

About This Project

This project is built with Django and Django REST Framework. It provides a customizable API rate limiting system where each API key and endpoint can have its own limits. Redis is used as a fast, distributed backend to track requests.

How It Works

  1. Every API request must include a valid X-API-Key header.
  2. Redis tracks the number of requests per key per endpoint.
  3. Requests exceeding the limit return a 429 Too Many Requests error.
  4. API responds with headers: X-RateLimit-Limit and X-RateLimit-Remaining for monitoring.

How to Test

You can test the API using Postman, cURL, or any HTTP client.

Try the API

You can test the API on your local machine or on the deployed Render server.

Localhost

URL: http://127.0.0.1:8000/api/test/

Example using cURL:

curl -H "X-API-Key: YOUR_API_KEY" http://127.0.0.1:8000/api/test/

Deployed on Render

URL: https://api-rate-limiter-lo1o.onrender.com/api/test/

Example using cURL:

curl -H "X-API-Key: YOUR_API_KEY" https://api-rate-limiter-lo1o.onrender.com/api/test/

Replace YOUR_API_KEY with a valid API key created in Django admin.

Project Endpoints

  • /api/test/ - Test endpoint (10 req/min)
  • /api/hello/ - Hello endpoint (10 req/min)
  • /api/profile/ - Profile endpoint (10 req/min)
  • /api/login/ - Login endpoint (20 req/min)
  • /api/purchase/ - Purchase endpoint (15 req/min)

Notes

Make sure your REDIS_URL and API keys are configured correctly for both local and deployed environments.
